## What to build

The `match-flow.spec.ts:120` test ("opens a tournament, plays a match, and closes it against the CueScore mock") has a race: after `await playTurn(page, 180, playerBId)` (which throws 180 and expects B to be the next active player), then an UNDO click, then `waitForActivePlayer(page, playerAId)` waits for the player-card's `data-active` to be `"true"`. The page renders faster in production than in dev, so the assertion sometimes catches the page before it has applied the UNDO's active-player update.

The test was passing in dev mode because the dev server's slow HMR / compile time gave the page enough wall-clock to settle before the assertion fired. After the containerised test runner was switched to a production build, the test fails deterministically (sometimes after Playwright retries) at the same `waitForActivePlayer` call.

The right fix is to wait on a stable page signal that the UNDO has been applied (e.g. the throw-history UI updating, the active-player indicator, or a server-state read) before asserting on `data-active`. Avoid hardcoded sleeps.
